# 機能まとめ

## 1. アプリの目的
バスケットボールのチーム・選手・試合・選手ごとのスタッツを管理する
- チームを登録・管理する
- 選手を登録・管理する
- 試合を登録・管理する
- 試合ごとの選手スタッツを登録・管理する
- 登録した情報を一覧・詳細画面で確認する

## 2. 管理するデータ
| データ | 内容 | 
| :----: | :----: | 
| チーム | チーム名、チームカラー |
| 選手 | 所属チーム、選手名 | 
| 試合 | 試合日時、ホームチーム、アウェイチーム | 
| スタッツ | 試合ごとの選手の成績 | 

## 3. チーム管理機能
#### チーム一覧
登録されているチームを一覧表示する
```
チーム一覧

○○高校
△△高校
□□高校

[チームを登録]
```

#### チーム登録
新しいチームを登録する
```
入力項目：
・チーム名(必須)
・チームカラー*

* チームカラーの入力は任意だが、未入力なら#FFFFFFを自動設定
```

#### チーム詳細
チームの情報を確認する
```
チーム名：○○高校

所属選手
・田中 太郎
・佐藤 次郎
・鈴木 三郎

[編集]
```

#### チーム編集
登録済みのチーム情報を変更する
```
チーム編集

チーム名[ 〇〇高校 ]
チームカラー[ #FFFFFF ]


[変更を保存][キャンセル]
```

```
・氏名(漢字)
・氏名(かな)
・背番号
・出身校
・身長(cm)
・体重(kg)
1人の選手は1つのチームに所属する
```
```
選手登録
所属チーム
[ ○○高校 ▼ ]

氏名(漢字)*
[ 田中 太郎 ]

氏名(かな)*
[ たなか たろう ]

背番号*
[ 4 ]

出身校*
[ 北中学校 ]

身長
[  ]

体重
[  ]


※ 所属チームは登録後に変更できません。
登録内容を確認してから登録してください。
登録後にチームを間違えた場合は、スタッツが登録されていなければ選手を削除して、正しいチームで再登録してください。

        [登録]
```

```

```

## 5. 試合管理機能
#### 試合一覧
登録されている試合を一覧表示する
```
試合一覧

2026/09/01
○○高校 20 - 20 △△高校 [スタッツを登録する]

2026/09/05
□□高校 20 - 20 ○○高校 [スタッツ登録済]

[試合を登録]
```

#### 試合登録
試合を登録する
```
入力項目：
・試合開始日時
・ホームチーム
・アウェイチーム
・ホーム最終スコア
・アウェイ最終スコア

ホーム・アウェイを明確に分ける。
また、
ホームチームとアウェイチームに同じチームを設定できない
ようにする
```

#### 試合詳細
1試合に出場した選手のスタッツをまとめて確認できるようにする
```
試合詳細

2026/09/01  19:00

○○高校
   VS
△△高校

--------------------------------

選手        得点   3P   2P   FT   REB  STL
田中 太郎    18    3/5  4/8  1/2   7    2
佐藤 次郎    12    1/3  4/6  1/2   5    1
鈴木 三郎     8    0/2  4/7  0/0   3    0

[スタッツを編集]
```

## 6. スタッツ管理機能
選手と試合の組み合わせごとにスタッツを管理する

#### 登録する項目
- 3P試行回数
- 3P成功回数
- 2P試行回数
- 2P成功回数
- FT試行回数
- FT成功回数
- オフェンスリバウンド
- ディフェンスリバウンド
- スティール
- シュートブロック
- ターンオーバー
- パーソナルファウル
- テクニカルファウル
- ファウルオン
- 退場回数
- 試合出場時間

#### 自動計算する項目
- 総得点 (3P成功 × 3 + 2P成功 × 2 + FT成功)
- 3点シュート成功率 (3P成功 ÷ 3P試行 × 100)
- 2点シュート成功率 (2P成功 ÷ 2P試行 × 100)
- フリースロー成功率 (FT成功 ÷ FT試行 × 100)
- 総リバウンド数 (オフェンスリバウンド + ディフェンスリバウンド)

理由：登録・更新時にデータの矛盾をなくすため

## 7. 検討したルール等
#### チーム
- 選手は1つのチームに所属する
- 過去の所属チーム履歴は管理しない

#### 選手
- 過去の所属チーム履歴は管理しない
- 選手の所属チームは登録後に変更できない
- 登録時にチームを選択し、以降は固定する
- 登録を間違えた場合は、選手を削除して正しいチームで再登録する
- 選手の削除についてはスタッツが存在する選手は削除できない(外部キー制約により管理)

#### 試合
- 試合にはホームチームとアウェイチームがある
- ホームチームとアウェイチームは同一にできない
- スタッツテーブルとは別で、最終スコアのデータを持たせる

#### スタッツ
- 1選手につき、1試合1スタッツ
- 3P・2P・FTの成功回数は試行回数を超えない
- スタッツの数値は0以上
- 出場時間を記録できる
- 成功率・得点・総リバウンドなどは必要に応じて自動計算する
- スタッツ登録時は、試合のHOMEチームまたはAWAYチームに所属する選手のみ登録可能とする
- 備考：選手が試合のホームチームまたはアウェイチームに所属していることをアプリケーション側で検証する

### その他設計
- 一覧画面では持っている情報を全て表示しない
∵ 一覧画面にある情報が多すぎると画面が横長になって見にくくなる、一覧画面で全情報表で確認できるなら詳細画面は不要になる
- 一覧画面には最小限の情報 + 詳しく見る(詳細画面への遷移リンク)
- チーム、選手、試合のIDの型は自動採番に変更 
∵ ユーザーがわざわざ最新のデータの各種IDを確認してから、手打ちする必要性はアプリとして不要
