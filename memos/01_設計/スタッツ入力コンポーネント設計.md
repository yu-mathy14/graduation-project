# スタッツ入力画面 コンポーネント設計

## 1. コンポーネント構成

```text
StatsNewForm                  … スタッツ入力画面全体とステップを管理

├── PlayerSelect              … 出場選手を選択する

└── PlayerStatsInput          … 1人分のスタッツを入力する
```

## 2. Props設計（主要コンポーネント）
| コンポーネント | 受け取るProps（型） | 親へ返すコールバック |
|---|---|---|
| StatsNewForm | `gameId: number`<br>`homeTeamName: string`<br>`homePlayers: Player[]`<br>`awayTeamName: string`<br>`awayPlayers: Player[]` | なし |
| PlayerSelect | `players: Player[]`<br>`selectedPlayerIds: number[]` | `onChange(playerId)` |
| PlayerStatsInput | `player: Player`<br>`stats: PlayerStats \| undefined` | `onChange(playerId, field, value)` |

## 3. 各コンポーネントの役割
| コンポーネント | 役割 |
| ----- | ----- |
| StatsNewForm | 画面全体の状態・ステップ・選手ごとのスタッツを管理する |
| PlayerSelect | チームの所属選手を表示し、出場選手を選択する |
| PlayerStatsInput | 1人分のスタッツ入力欄を表示する |

## 4. `PlayerSelect` と `PlayerStatsInput` にコンポーネントを分割した理由

最初は`StatsNewForm`に選手選択とスタッツ入力の処理をまとめていたが、画面が複雑になるため、役割ごとにコンポーネントを分割した。

`PlayerSelect`は出場選手の選択を担当し、<br>
`PlayerStatsInput`は1人分のスタッツ入力を担当する。

これにより、`StatsNewForm`は画面全体の状態やステップ管理に集中できる。

また、`PlayerSelect`と`PlayerStatsInput`はホームチームとアウェイチームの両方で再利用できるため、同じ処理を重複して記述せずに済む。

## 5. `currentHomePlayerIndex` / `currentAwayPlayerIndex` の考え方

スタッツ入力を1選手1画面で行うため、現在どの選手を表示しているかを`index`で管理する。

例えば3人の選手を選択した場合、
```
0 → 1人目
1 → 2人目
2 → 3人目
```
となる。

`currentHomePlayerIndex`はホームチーム、<br>
`currentAwayPlayerIndex`はアウェイチームの現在入力している選手の位置を表す。

「次の選手へ」を押した場合はindexを1増やし、<br>
「前の選手へ」を押した場合はindexを1減らすことで、表示する選手を切り替えている。

## 6. 1選手1画面方式を採用した理由

スタッツは入力項目が多く、複数選手分を1画面に表示すると画面が長くなり、入力する選手が分かりにくくなる。<br>
そのため、出場選手を選択した後は、1選手ずつスタッツを入力する方式とした。<br>
「次の選手へ」「前の選手へ」で選手を切り替え、入力したスタッツは`StatsNewForm`のStateで保持する。<br>
これにより、画面上は1人分だけを表示しながら、最終的には全選手分のスタッツをまとめて登録できる。<br>
