# 削除機能設計
全テーブル共通の削除機能を設計する。

## イメージ
```
画面表示
  ↓
削除可否を確認
  ↓
┌───────────────┐
│ 削除可能        │ → 削除ボタン 有効
│ 削除不可        │ → 削除ボタン 無効
└───────────────┘
                  ↓
          削除ボタンを押す
                  ↓
          「本当に削除しますか？」
             ↓           ↓
         キャンセル    削除する
                         ↓
                  Server Action
                         ↓
                    再度削除可否判定
                    ↓            ↓
                  削除          エラー
```

## 削除機能の流れ
0. 詳細画面表示<br>
詳細画面に編集ボタンの他、削除ボタンもある状態。

1. 削除可否を判定(1回目：画面側)<br>
UI向上のため
| 削除対象候補 | 削除可能条件 |
| :----: | :----: |
| 選手 | スタッツなし |
| 試合 | スタッツなし |
| チーム | 所属選手も試合参加歴もなし |
| スタッツ | × |

2. 削除ボタンの切替<br>
- 削除可能な場合は削除ボタンを有効
- 削除不可な場合は削除ボタンを無効

3. 削除ボタン押下後、削除確認ダイアログを表示<br>
「この〇〇を本当に削除しますか？」<br>
※ 〇〇は選手/試合/チームのいずれか

4. [削除する]押下後、削除可否を判定(2回目：Server Action側)<br>
データ保護・安全性のため

※ [キャンセル]押下の場合はデータを削除せず、確認ダイアログを閉じて詳細画面に留まる。

5. 削除結果の処理<br>
削除可能な場合ははデータを削除し、一覧画面に戻る。

削除不可の場合はエラーメッセージを表示し、[了解]押下で詳細画面に戻る。
