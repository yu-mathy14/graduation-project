6. FT成功 ＞ FT試投の場合、エラーになる
7. PF + TF ≦ 5の場合、登録できる
8. PF + TF ＞ 5の場合、エラーになる

#### 19. 「次の選手へ」の動作
1. 正しいスタッツの場合、次の選手へ進める
2. 不正なスタッツの場合、エラーメッセージが表示される
3. 不正なスタッツの場合、次の選手へ進まない
4. エラーを修正すると、エラーメッセージが消えて次の選手へ進める

#### 20. 「登録」の動作
1. 選択した全選手のスタッツが正しい場合、登録できる
2. 1人でも不正なスタッツがある場合、エラーメッセージが表示される
3. 1人でも不正なスタッツがある場合、DB登録されない
4. 全選手の検証に成功した場合、`createStats()` が実行される

### 整合性チェック
#### 登録対象の整合性
1. 選択した選手のスタッツだけが登録対象になる
2. 選択を解除した選手のスタッツが登録対象に含まれない
3. 選択した選手と登録対象の選手が一致する
4. 選択した全選手のスタッツがYup検証の対象になる
5. 選択した全選手のYup検証に成功した場合、登録対象のスタッツがcreateStats()に渡される

### 「変更を保存」の動作
#### 19. 複数エラーの表示
1. 1選手に複数のエラーがある場合、すべてのエラーメッセージが表示される
2. 複数選手にエラーがある場合、すべての選手のエラーメッセージが表示される
3. エラーメッセージに背番号と選手名が表示される
4. エラーがある場合、DBへ保存されない
5. エラーをすべて修正して保存すると、DBへ保存できる

#### 20. 保存成功時の動作
1. 編集したスタッツがDBへ正しく保存される
2. 保存完了後、試合詳細・スタッツ一覧画面へ戻る

### 整合性チェック
#### 編集対象と保存データの整合性
1. 表示されている全選手のスタッツを編集できる
2. 編集した選手のスタッツだけが更新対象になる
3. 選手IDと対応するスタッツが正しく更新される
4. Yup検証に成功した全選手分のスタッツが`updateStats()`に渡される
5. Yup検証に失敗した場合、`updateStats()`が実行されない
